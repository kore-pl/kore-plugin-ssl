# kore-plugin-ssl

Этот репозиторий реализует плагин управления TLS-сертификатами для kore (id `ssl`). Каталог сертификатов фиксирован (`KORE_SSL_CERT_DIR`, по умолчанию `/etc/kore/ssl`); RPC не принимает произвольные пути. Все операции работают с реальными файлами, без фейковых списков в памяти. Только стандартная библиотека Go + pluginapi: никаких сторонних ACME-библиотек и встроенных certbot/acme. `lifecycle=lazy`: продление инициируется ядром, без внутренних таймеров. Плагин не пишет конфигурацию веб-сервера: привязка и редирект 80→443 принадлежат плагину site; здесь только регистрируется принадлежность и выносится решение только для чтения.

## Что делает проект

- **Протокол**: `kore.plugin.v1`, `lifecycle=lazy`, `depth_level=production`.
- **Методы**: `ssl.list` / `import` / `selfsign` / `renew` / `verify` / `expiring` / `renew.set` / `acme.status` / `acme.issue`; `verify` выполняет реальный TLS-handshake.
- **Реальные файлы**: фиксированный каталог, никаких произвольных путей; каждый сертификат разбирается по-настоящему.
- **Граница только для чтения**: `site.bindSSL` / `unbindSSL` / `setRedirect` принадлежат плагину site; `boundary_test.go` блокирует выход за рамки.
- **Ноль таймеров**: продление по событию ядра `event:cert.renew_due`; без резидентных процессов.
- **ACME**: встроенная выдача или `engine=external` для certbot/acme.sh; `acme.status` проверяет локальный клиент.

## Быстрый старт

```bash
make check    # gofmt → vet → test

```

Плагин запускается оболочкой kore по требованию; `info.json` объявляет полномочия и `requires_kore`.

## Частые вопросы

**В: Нужен аккаунт?**
Нет. Никаких аккаунтов, онлайн-проверок и скрытой телеметрии; конфигурация — открытый текст.

**В: Где плагины?**
Каждый плагин в своём репозитории `kore-plugin-<id>` и зависит только от `kore/pkg/pluginapi`.

**В: С чего начать?**
Прочитайте протокол и таблицу методов в README, затем полномочия в `info.json`.
